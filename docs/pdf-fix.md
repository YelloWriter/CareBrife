# PDF 저장 수정 — 2026-09-28

기존 `PDF 저장하기`는 `window.print()`만 호출했습니다. 인쇄 창을 지원하지 않거나 호출이 무시되는 앱 내 브라우저에서는 PDF 파일을 받을 수 없었습니다.

## 수정

- 브라우저 메모리에서 pdf-lib로 PDF 생성 후 Blob 다운로드. 서버·외부 서비스에 리포트 내용을 전송하지 않음.
- A4, 한국어 글꼴, 로고, 작성일, 항목별 구분, 페이지 번호. 긴 내용은 다음 페이지에 계속 표시.
- 다운로드가 시작되지 않을 때 쓸 재다운로드·PDF 열기 링크. 파일 생성 중 버튼 비활성화, 실패 재시도, 수정·이탈 시 기존 Blob URL 해제.
- 미지원 문자를 무시하지 않고 수정 안내. 실제 저장 여부를 감지한 것처럼 표시하지 않음.
- 정적 Noto Sans KR 전용 글꼴과 OFL 포함. 생성법은 `public/fonts/README.md`.

## 검증

- 타입 검사·프로덕션 빌드 통과. 전체 회귀 21개 통과, 선택 음성 모델 검사 1개 생략. 글꼴 최종 보정 후 관련 13개 검사 재통과.
- Chromium에서 인쇄 함수를 실패하도록 만들어도 다운로드 이벤트와 실제 PDF 파일 수신 성공.
- 글꼴 로딩 실패→재시도, 재다운로드 링크, 내용 수정 후 저장, 나가기 대화상자의 저장, 생성 중 취소 확인.
- 한글 원문 추출, 70개 가상 기록·마지막 질문 보존, A4 페이지/여백 검사. 1페이지·6페이지 PDF 전체를 Poppler로 렌더링해 표시 확인.
- 초기에 텍스트 추출은 정상이지만 한글이 실제 화면에서 누락되는 글꼴 서브셋 문제를 발견해 보정. 실제 출력 검증 없이 텍스트 검사만으로 통과시키지 않음.
- 실제 사용자 건강정보를 QA 파일로 사용하지 않음. 앱 내 브라우저의 다운로드 알림·저장 처리는 브라우저 자체 기능의 영향도 받으므로 다운로드를 요청했다는 사실과 실제 파일 저장을 구분함.
